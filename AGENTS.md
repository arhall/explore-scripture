# AGENTS.md

Quick, concise orientation for agents working in this repo. Use this before
diving into details in `CLAUDE.md`.

## Project Snapshot
- **Product**: Explore Scripture, a static Bible study platform.
- **Stack**: Eleventy (11ty) + Nunjucks + vanilla JS + CSS.
- **Deploy**: Cloudflare Pages; build output `_site/`.
- **Design**: Mobile-first, themeable via CSS custom properties.

## Fast Start (Local)
```bash
npm install
npm run dev
```
Other common commands:
```bash
npm run build
npm run build:analyze
npm run dev:pages
npm run test
npm run lint
```

## Core Structure (Know These Paths)
- **Layouts**: `src/_includes/layouts/`
  - `base.njk` full feature layout (nav, toggles, PWA, etc.)
  - `base-minimal.njk` simplified layout
  - `book.njk` book pages
  - `category.njk` category pages
- **Pages**: `src/*.njk` (home, books, categories, entities, map, links, etc.)
- **Data**: `src/_data/` (books, categories, videos, cross-refs, etc.)
- **Styles**: `src/styles.css` (large monolithic stylesheet)
- **Assets/JS**: `src/assets/` (interactive features, loaders, telemetry)

## High-Impact Features (Where to Look)
- **Chapter Reader**: `src/assets/chapter-reader.js`
- **Commentary System**: `src/assets/commentary-reader.js`
- **Search Engine/UI**: `src/assets/search-engine.js`,
  `src/assets/search-interface.js`
- **Scripture Widget**: `src/assets/scripture-widget.js`
- **Theme System**: `src/assets/theme-manager.js`
- **Map Page**:
  - Template: `src/map.njk`
  - JS: `src/assets/js/map/`
  - Map styles: `src/assets/map/styles/`
  - CSS: `src/styles.css` (map section near end)
- **Genealogies**: `src/genealogies.njk` (D3-based visualization)

## Data Updates (Common Tasks)
- **Book summaries/metadata**: `src/_data/books.json`
- **Categories**: `src/_data/categories.js`
- **Bible Project videos**: `src/_data/bibleProjectVideos.json`
- **Cross references**: `src/_data/crossReferences.js`
- **Entities**: generated via `scripts/entity-processor.js`

## Build & Data Generation
- Search data generated by `generate-search-data.js`.
- Build output goes to `_site/`.

## Architecture Notes (Short)
- Eleventy generates static pages from data + Nunjucks templates.
- JS is modular; many features load lazily via `src/assets/module-loader.js`
  and `src/assets/bundle-optimizer.js`.
- CSP is defined in `base.njk`; new external resources must be added there.

## Styling Conventions
- Use CSS variables; avoid hard-coded colors.
- Keep layouts mobile-first; test at narrow widths.
- Map page uses dedicated styles in `src/styles.css` (search for `.map-`).

## Testing
- JS tests: `npm run test`
- Selenium tests: `npm run test:selenium`
- iOS tests: `npm run test:ios`

## Deployment
- Cloudflare Pages; build command `npm run build`, output `_site/`.

## When You’re Unsure

## Supply-chain and security gates

These gates are mandatory for every change in this repository, including code, configuration, documentation, generated files, and dependency changes. They supplement the project-specific guidance above; they do not waive it.

Before editing:

- Run `git status --short --branch` from the repository root and preserve unrelated working-tree changes. If this project has no Git metadata, record that fact and identify the containing repository or tracking mechanism.
- Identify the project manifest, package manager, lockfile, and existing validation/security commands.

After every change:

- Run the relevant tests and lint or type checks for the affected project.
+ Run the supported ecosystem security check: `npm audit`, `pnpm audit`, the repository's configured Python audit command, `govulncheck`, or the project's documented equivalent.
- Run existing static security checks or security test suites, including secret scanning or `retire`, when the project defines them.
- Run `git diff --check` and record the exact commands and results. A skipped, unavailable, or network-blocked check is blocked or unverified, not clean.

For dependency or lockfile changes:

- Use the existing package manager and update the supported lockfile in the same change. Do not claim remediation while manifests and lockfiles are inconsistent.
- Run the installed supply-chain-risk-auditor collector and render reports outside the repository. Recheck direct and transitive advisories, abandoned/deprecated packages, install scripts, and lockfile coverage; treat unavailable measurements as unassessable.
- Keep production dependency updates visible for review, do not automerge production dependencies, and do not add Dependabot version-update configuration when Renovate is enabled.

For newly cloned, created, or restored repositories:

- Complete the pre-edit status and manifest inventory before the first substantive change.
- Add or verify a project-local `AGENTS.md`, a supported lockfile where the package manager permits it, and the prepared Renovate policy for GitHub-hosted repositories.
- Run at least one security check before the first change is complete and repeat it after the change.
- Record registry, tool, GitHub-authentication, or collector blockers in `SUPPLY_CHAIN_TODOS.md` or the project's existing tracker.
